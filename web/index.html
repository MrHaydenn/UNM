Download WireGuard for Windows from the official installation page.

Using Add Empty Tunnel

  1. In WireGuard, choose Add Tunnel → Add Empty Tunnel. Give it a name such as UNM-PC.
  2. Keep its [Interface] and PrivateKey lines on your PC. Copy only the Public key shown above the editor.
  3. In UNM, choose Add host → Create a new WireGuard peer. Enter a host name, leave the address blank, and paste that public key into Host public key.
  4. Click Add host. UNM configures the VPS peer and shows your host settings. Click Copy settings for empty tunnel.
  5. Paste those settings on a new line below your existing PrivateKey line. Keep just one [Interface] section. Click Save, then Activate.
  6. Click Refresh in UNM and look for a recent handshake. Allow the service you want to forward through Windows Firewall.

Alternative: import a generated file

Leave Host public key blank when adding the peer. UNM generates a complete configuration. Save it immediately, then use Add Tunnel → Import tunnel(s) from file in WireGuard and activate it. You do not need an empty tunnel for this method.

Never share a PrivateKey or a screenshot containing one. If a key was shared, create a fresh empty tunnel before registering its public key.

Firewall access

Forwarding rules open their selected ports and protocols automatically. Ranges use 20000-20010 format; forwarding destination ranges must have the same number of ports. Add separate allowances for other services in the reserved range. Disabling an entry removes UNM’s allowance; existing system rules still apply.

firewalld service

Stopping firewalld removes firewall protection for all services on the VPS. Preview changes are saved only.

Websites and SSL

Route a domain to a website on a WireGuard host. Automatic SSL requests and renews Let’s Encrypt certificates and redirects HTTP to HTTPS. WebSockets are supported automatically.

Point the domain’s DNS to the VPS first. Ports 80 and 443 must reach Caddy; NGINX Proxy Manager must release those ports before live setup.

Authoritative DNS server

Cloudflare delegation · start here

Keep mrhaydenn.us on Cloudflare. Delegate only minecraft.mrhaydenn.us to this DNS server using the records below. Test the VPS DNS server before adding NS records. Changing delegation changes where resolvers look up every record below that subdomain.

A record: trigun → your VPS public IP. For a non-default Java server port, add an SRV record named _minecraft._tcp.trigun with content such as 0 5 20080 trigun.minecraft.mrhaydenn.us. Create the forwarding rule separately. DNS does not open ports.

One VPS is a single point of failure. A second independent nameserver can be added later; two names pointing to the same VPS do not provide redundancy. This server answers authoritative queries only and has recursion disabled.

Integration keys

Named keys let MMSM publish DNS records in one configured zone. They do not grant access to the panel, firewall or SSH.

Rotate a lost key to replace its token while keeping ownership of its DNS records. Revoking a key blocks future requests; existing records remain published.
